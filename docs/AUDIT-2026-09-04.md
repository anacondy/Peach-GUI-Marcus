## 1. What this repo is

An **archiso profile** that bakes a Sway+waybar desktop ("Marcus Mix") into a
live/installer ISO for an HP 14s. It is not an app; the "backend" is the set of
build scripts (`scripts/build-test-iso.sh`, `customize_airootfs.sh`) and the
"frontend" is the desktop config under `airootfs/root/.config/`. Wiring questions
therefore reduce to: *does the build produce an image whose configs reference
only things that are installed and present?* That is exactly what §2 checks.

## 3. Performance findings (the 60/90/120/144 Hz ask)

Nothing in the old tree accounted for refresh rate at all; a hard-coded latency
number is wrong on every panel except the one it was measured on. New logic
(`perf-profile.sh`), all `RAN` against a stubbed swaymsg:

* `max_render_time` = `round(1000/Hz − 4ms)`, clamped to `[1,16]`: 60→13ms,
  90→7, 120→4, 144→3, 240→1 (floor), 30→16 (ceiling). Per-output, so a mixed
  setup is not given one number.
* A pixel-throughput score (`MP/s = Σ(w·h·Hz)`) picks a blur/shadow tier:
  1080p@60 (the target laptop)=high (= today's look), 1080p@144=high,
  1440p@120 / 4K@60=balanced, 4K@144=light, dual-4K@144=off; battery and a
  software/pixman renderer derate.
* Idempotent: a reload that changes nothing issues no `swaymsg` at all.
* `WLR_RENDERER=pixman` in the VM is intentional (the only renderer that works
  under virtualisation) and is why blur/rounding do not appear there.

**Not verifiable here:** that the tier table's FPS assumptions hold on real
silicon, or any sustained-FPS number. That requires the built ISO on a GPU
(`N/A-here`). The one thing this environment *can* prove is that the logic is
deterministic and clamped correctly, which is exactly what the tests assert.

## 4. Corrections to the other branch's ANALYSIS.md

* "`profiledef.sh` references non-existent `.automated_script.sh`" — partly
  right, but the real bug was `.zlogin` *running* that unshipped script; the
  `file_permissions` entry was merely dead. Fixed both.
* "`spotlight.sh` … missing `fi`" — not in the branch diff; the shipped file was
  already syntactically fine (verified `bash -n`). The real spotlight issues
  were the world-readable index and the `%[a-zA-Z]` field-code mangling.
* `build-test-iso.sh` "fixed to avoid corrupting package list" — direction right,
  but the fix used a `mkarchiso -p <file>` flag that mkarchiso does not offer for
  a package *list file*, and `|| true` that masked all failure. Replaced with
  profile staging.
* The branch deleted `.zlogin`/`.zprofile`, which is exactly the files that make
  tty1 autostart sway — a regression, not a cleanup.
